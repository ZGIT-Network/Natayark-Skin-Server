# 上传奖励、资源限制与材质删除

升级已有站点时先备份数据库和材质目录，再执行迁移、构建并重启：

```sh
npm ci
npm run migrate -- --apply
npm run build
```

PowerShell 下也可直接运行 `node --import tsx scripts/migrate.ts --apply`，避免 npm 参数转发差异；预演输出不表示迁移已经应用。

迁移 `005_texture_rewards.sql` 新增两张独立记录表，不改变原 Blessing Skin 表字段，不重算已有积分。新站初始化已包含这些表。

## 奖励规则

- 保留原先公开及私有网页上传的配置奖励，净成本可以为负。使用解码后的尺寸和 RGBA 像素去重，忽略 PNG 压缩方式、元数据、IEND 尾随数据及完全透明像素中的 RGB。
- 同一用户的相同像素内容只奖励一次。领奖记录在删除后保留；重传、切换模型或改变编码不会重置。
- 每人每日默认最多奖励 10 次。后台「积分规则」可设置 `upload_reward_daily_limit`，0 表示停发；未领奖的上传按正常存储及衣柜费用结算。
- 公开及私有网页上传共用内容去重与每日上限；Yggdrasil 上传和批量导入不发奖，隐私切换不追发。上传页展示费用及可能获得的奖励，以服务端实际结算为准。
- 用户行锁保护内容去重、每日计数和积分；删除或转私有只按实际获得且尚未收回的奖励扣回，避免重复扣回。
- 原材质在该用户首次上传、删除或切换隐私时补建内容记录，不发放新奖励、不追溯调整积分。原文件缺失或损坏时无法恢复其像素指纹。

像素不同的图片仍可能是同一创作，每日上限用于约束这类变化。不同账号分别计数，这不等于跨账号反滥用系统。

## 请求与计算预算

bcrypt、Argon2 和旧 bcrypt 客户端密钥采用异步原生计算，保留原密码格式和盐配置。默认同时执行 2 项密码计算、最多等待 16 项，超出返回 503 和 `Retry-After`。

所有路由有每 IP 每分钟 1000 次的基础预算；认证入口另有默认每 IP 每分钟 60 次的共享预算，覆盖网页登录、Yggdrasil、Connect 和 token 别名。Yggdrasil 密码登录继续按账户每分钟限制 20 次，在解析请求体后计算账户键。更换用户名不能绕过 IP 预算。

```dotenv
AUTH_IP_RATE_LIMIT=60
PASSWORD_CONCURRENCY=2
UPLOAD_CONCURRENCY=2
```

以上预算按 Node.js 进程计算，多实例部署应在反向代理配置聚合限流。网页与 Yggdrasil multipart 上传在读取时使用业务文件上限，默认 1 MiB，硬上限 64 MiB；每次最多 1 个文件、16 个字段，每字段最多 64 KiB。默认同时处理 2 个上传请求，超出返回 503。总请求超时 120 秒，连接空闲超时 30 秒。

## 缓存与删除语义

角色档案、头像、材质预览、旧皮肤/披风地址和按 ID 下载需重新验证缓存；按内容哈希的原始文件保留长缓存。

“私有”表示不进入公共皮肤库及限制站内收藏、应用，不保证图片链接保密。已知哈希者仍可下载有材质记录引用的图片，上传与管理页面会说明这一含义。

删除最后一条材质记录后，源站哈希接口立即返回 404，包括带旧 ETag 的请求；未提交的上传文件也不会被公开提供。若其他记录仍引用同一哈希，文件仍可访问。已有下载、浏览器缓存与 CDN 副本无法通过源站删除撤回。

## 延迟文件回收

服务每小时扫描一次，每次最多处理 500 个候选，默认保留 24 小时。只检查名称为 SHA-256 的普通文件，忽略目录及符号链接；回收与原生上传、批量导入使用同一数据库文件锁，等待事务结束后重新检查引用和保留期，避免删除并发上传刚引用的文件。事务回滚留下的孤立文件也适用。

```sh
# 预演，只输出计数
npm run textures:gc
# 应用回收，仍遵守保留期和引用检查
npm run textures:gc -- --apply
```

```dotenv
TEXTURE_GC_RETENTION_HOURS=24
TEXTURE_GC_INTERVAL_MINUTES=60
```

保留期最少 1 小时。同一材质目录只能服务一个数据库命名空间；多个 Node.js 实例须共享该数据库、表前缀及材质目录。带表前缀的实例若仍使用默认 `storage/textures`，回收会跳过，需为其配置独立目录，避免开发副本清理共享资源。若旧 PHP 或外部程序仍在写同一目录，应停止这些写入或协调相同锁协议，再启用物理回收。

## 响应头、时间与数据库 CI

应用统一返回 `nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy` 和限制 base URL、插件对象、页面嵌入的基础 CSP。生产环境在可信 HTTPS 请求上返回 HSTS。当前 CSP 尚未约束脚本来源，保留内联脚本、自定义 JS 和验证码；严格脚本 CSP 应逐步引入，见[部署说明](deployment.md)。

保留原站本地 DATETIME 格式，针对每个时间点应用时区规则，不再固定使用启动时偏移。旧格式无法区分夏令时结束时重复出现的同一小时：解析时选较早时刻，不存在的本地时刻向后平移。升级不会批量将旧数据转换为 UTC。

数据库 CI 保留 MySQL 5.7，增加 MySQL 8.4 独立任务。新增配置不等于已经获得远程运行结果；应以具体 CI 检查为准。回归覆盖等价 PNG、并发领奖、每日上限、删除重传、奖励扣回、回滚、动态缓存、源站撤销、回收与并发上传、流式限制、密码事件循环、限流、响应头和夏令时。

参考：[Fastify 限流](https://github.com/fastify/fastify-rate-limit)、[multipart 流式限制](https://github.com/fastify/fastify-multipart)、[异步 bcrypt](https://github.com/napi-rs/node-rs/tree/main/packages/bcrypt)、[Temporal 时区](https://tc39.es/proposal-temporal/docs/zoneddatetime.html)。
